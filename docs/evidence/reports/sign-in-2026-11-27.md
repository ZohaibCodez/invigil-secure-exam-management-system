# Sign-in navigation browser follow-up

**Date:** 2026-11-27

**Environment:** development preview, fictional accounts

**Outcome:** passed the focused checks below

## Defect and correction

The earlier recovery run showed a successful server session while `/login`
remained on the loading form. Clearing the entire query cache detached the
mounted session observer.

The corrected client retains that observer, removes non-session private query
data, and resets/refetches the session. Sign-out failures now remain visible
rather than being silently treated as success.

## Executed checks

| Check | Observed result |
| --- | --- |
| Candidate UI sign-out | Returned to the public landing page; server session reported no user |
| Examiner email/password form | Automatically left `/login` and displayed the examiner dashboard without manual navigation or refresh |
| Examiner UI sign-out | Completed before the next login |
| Candidate demo-button login | Automatically left `/login` and displayed the candidate dashboard |
| Incorrect password | Remained on `/login`, showed an invalid-credentials error and left Continue enabled |

The follow-up did not create additional examination fixtures or repeat the
scratchpad tests. The candidate email/password form was not separately repeated;
the candidate used the demo button.

The tester returned a still image of the invalid-password state. It remains a
Replit observation image; no image-file or continuous-video export was available.

## Automated regression

`pnpm run test:auth-cache` verifies sign-in/sign-out updates to the mounted query
observer and removal of the previous user's cached private data.
